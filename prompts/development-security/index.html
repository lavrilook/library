Правила безопасности разработки

Промпт для проекта: ключи, переменные окружения и проверка изменений перед Git.

Как пользоваться

Передай промпт агенту перед началом разработки. Проверь созданные правила и исключения Git. Реальные секретные значения в сообщение не вставляй.

Промпт

Перед началом разработки установи обязательные правила безопасности для всего проекта. Проект будет храниться в приватном GitHub-репозитории. СТРОГО ЗАПРЕЩЕНО добавлять в Git или GitHub: Telegram Bot Token; API-ключи OpenAI, Anthropic, Google и других сервисов; пароли от баз данных, серверов, почты и сторонних сервисов; private SSH keys, приватные сертификаты и другие секретные ключи; файл .env с реальными значениями; Database URL с логинами, паролями или credentials; cookies, session-файлы, access tokens, refresh tokens и OAuth credentials; базы данных, логи и выгрузки с реальными персональными данными пользователей, включая телефоны, email, переписки и платёжные данные. Все секретные значения должны передаваться через переменные окружения. Создай файл .env для локальных секретов, добавь .env и другие секретные файлы в .gitignore, создай .env.example только с названиями переменных без реальных значений. Никогда не вставляй реальные ключи или пароли непосредственно в код. Перед каждым commit или push проверяй изменения и убедись, что в них нет секретов, токенов, паролей, credentials или персональных данных. Если обнаружишь потенциальный секрет — не добавляй его в Git, остановись, сообщи мне, какой файл содержит риск, и предложи безопасный способ хранения. Для production используй Variables / Secrets хостинга или другой предназначенный для этого secret manager. Эти правила действуют на протяжении всей разработки проекта.
